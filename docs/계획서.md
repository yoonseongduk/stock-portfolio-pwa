# 주식현황관리 — 계획서

## 1. 목표

안드로이드 폰에서 내 주식 현황(국내주식 + 미국주식)을 한눈에 보는
**개인용 앱**을 만든다. 거래소나 증권사 계정에 연결하지 않고, 내가 직접
입력한 데이터로 보유 현황 · 평가손익 · 수익률을 계산해서 보여준다.

## 2. 왜 이 방식인가 (결정된 사항)

| 결정 | 내용 | 이유 |
|---|---|---|
| 앱 형태 | **PWA**(Progressive Web App) | 구글 플레이 스토어에 올리지 않고도, 크롬 브라우저로 접속한 뒤 "홈 화면에 추가"만 하면 폰에 앱처럼 설치됨. 개발자 등록·심사 절차가 없어 초보자가 가장 빠르게 결과를 볼 수 있음 |
| 기술 스택 | HTML + CSS + JavaScript (순수, 빌드 도구 없음) | React·Vue 같은 프레임워크나 Webpack 같은 빌드 과정 없이, 파일을 열면 바로 동작. 디버깅이 쉽고 초보자가 코드 전체를 이해하기 좋음 |
| 데이터 저장 | 폰 안 `localStorage` (나중에 필요하면 `IndexedDB`) | 개인 금융정보이므로 외부 서버로 전송하지 않음. 전부 내 폰 안에만 저장됨 |
| 핵심 데이터 모델 | **거래내역**(날짜/종목/매수·매도/수량/단가/수수료)을 기록 → 보유수량·평균단가·평가손익·수익률은 **자동 계산** | 실제 증권사처럼 매매 기록만 쌓으면 나머지는 계산으로 유도되는 구조가 정확하고 나중에 확장하기 쉬움 (Sprint 1은 단순화를 위해 계산값을 직접 입력받고, Sprint 2에서 거래내역 기반으로 전환) |
| 환율 | 미국주식은 달러 기준 → 환율 반영은 나중 스프린트에서 처리 | 처음부터 환율 API까지 붙이면 복잡도가 커져서 MVP 범위를 넘어감 |

## 3. 스프린트 계획 (애자일: 작게 나눠서, 매 단계마다 직접 확인)

- **Sprint 0 — 뼈대**: 폰 홈 화면에 아이콘이 생기고 빈 화면이 열림.
  `manifest.json`(앱 이름/아이콘/색상 정의), `service-worker.js`(오프라인 캐시) 포함.
- **Sprint 1 — MVP**: 종목명/수량/평균단가/현재가를 직접 입력 →
  평가금액 · 손익 · 수익률과 총합을 목록으로 표시.
- **Sprint 2**: 거래내역(매수/매도) 입력 방식으로 전환, 평균단가 자동 계산.
- **Sprint 3**: 대시보드 — 총자산, 총손익, 종목 비중 차트, 수익률 순위.
- **Sprint 4**: 현재가 자동 조회 (국내/미국, 무료 데이터 소스 검토 후 제안).
- **Sprint 5**: 백업 내보내기/가져오기, 배당 기록.
- **Sprint 6 (제안, 미착수)**: 종목별 추세 분석
  - 가격 히스토리 차트(Sprint 4부터 자동조회 시 OHLCV를 날짜별로 쌓고 있음, `stockPriceHistory_v1`)
  - **과거 시세 채우기(backfill)**: 지금은 "조회" 버튼을 누른 날부터만 히스토리가 쌓여서,
    매수일~사용 시작일 사이의 과거 시세는 비어있음. 두 API 다 날짜 범위 조회가 되므로
    (공공데이터포털은 이미 범위 조회 방식, Twelve Data는 과거 데이터 전용 엔드포인트 필요)
    "종목의 첫 매수일부터 오늘까지 한 번에 채우기" 기능을 추가해야 진짜 매수 시점부터의
    추세를 볼 수 있음. 2026-11-06 논의.
  - 기업 분석 지표(PER/PBR/ROE 등) — **별도 데이터 소스 조사 필요**
    (공공데이터포털 주식시세정보에는 없음, 다른 공공데이터 또는 DART 전자공시 등 확인 필요).
- **백로그 (제안됨, 순서·스프린트 미정, 2026-11-06 등록)**:
  - *사용성 개선*: 거래내역 수정(지금은 삭제 후 재입력만 가능) · 보유 종목
    정렬/필터(수익률순·평가금액순) · 종목 카드 접기/펼치기(종목 많아지면 목록이
    길어짐 대비) · 당겨서 새로고침(pull-to-refresh)으로 전체 시세 갱신 ·
    조회 중 로딩 표시(버튼 스피너 등, 지금은 텍스트 상태 메시지뿐)
  - *시각화*: 종목별 미니 추이(스파크라인) — Sprint 4부터 쌓고 있는 가격
    히스토리(`stockPriceHistory_v1`)를 보유 종목 카드 안에 작은 선그래프로
  - *계산/데이터*: 환율 반영(미국주식 원화 환산, 국내+미국 총자산 통합 보기) ·
    매도 수수료를 반영한 실현손익 계산(지금은 수수료가 기록만 되고 계산엔 미반영) ·
    데이터 전체 초기화 버튼
  - *알림*: 목표가/손절가 알림 — PWA라 완전 자동(백그라운드)은 어렵고, 앱을 열었을 때
    체크하는 방식 정도로 제한될 가능성 있음(난이도 있어 뒷순위)
- **이후 (범위 밖, 더 큰 아이디어)**: 다중 계좌, 다크모드,
  증권사 계정 연동(오픈API 로그인 — 서버 없이는 비밀키 노출 문제가 있어 별도 검토 필요).

각 스프린트가 끝나면 사용자가 폰에서 직접 확인하고, "다음 스프린트 진행"을
승인해야 다음 단계로 넘어간다. 백로그 항목은 사용자가 지목하면 그때 스프린트로
편성한다.

## 7. 배포 (GitHub Pages, 2026-11-06)

- **배포 주소**: https://yoonseongduk.github.io/stock-portfolio-pwa/
- **저장소**: https://github.com/yoonseongduk/stock-portfolio-pwa (공개 — GitHub Pages가
  무료 개인 계정에서는 비공개 저장소를 지원하지 않아서 공개로 전환함. 소스코드는 누구나
  볼 수 있지만, 개인 금융정보는 소스코드에 없고 전부 각자 폰의 localStorage에만 저장되므로
  문제 없음. 비공개를 꼭 유지하려면 Netlify 등 비공개 저장소 배포가 되는 다른 호스팅으로
  바꿀 수 있음)
- **왜 호스팅으로 옮겼나**: 기존 PC 로컬 서버(`http://192.168.0.61:8000`)는 http라서
  보안 컨텍스트가 아니어서 서비스 워커(오프라인 캐시)가 제대로 등록 안 됐을 수 있음.
  GitHub Pages는 자동으로 https라 "진짜" 설치형 PWA(오프라인 동작 포함)가 됨. PC를
  켜놓지 않아도 폰에서 접속 가능.
- **중요 — 기존 테스트 데이터 이전 필요**: 브라우저 저장소는 **주소(origin)별로 분리**되므로,
  `192.168.0.61:8000`에서 입력했던 거래내역·API 키 등은 새 주소
  `yoonseongduk.github.io`로 자동으로 안 넘어옴. 기존 주소에서 "전체 백업 내보내기"로
  JSON 파일을 받은 뒤, 새 주소에서 "전체 백업 가져오기"로 불러오면 그대로 이어짐
  (Sprint 5에서 만든 백업 기능이 이 상황에 바로 쓰임).
- **자동 업데이트**: 코드를 고친 뒤 `git push`하면 GitHub Pages가 자동으로 다시 배포하고,
  폰에서 앱을 열 때마다 새 버전인지 확인해서 자동 반영됨(Sprint 5에서 구현).
  앞으로 코드를 바꾼 뒤에는 커밋·푸시까지 같이 해야 폰에 반영된다는 점 기억.


## 5. 테스트 방법 (초보자용)

자세한 내용은 아래 "6. 폰에서 테스트하는 방법"을 참고. 요약:

1. PC에서 간단한 로컬 웹서버를 띄운다 (Python 한 줄 명령).
2. PC와 폰을 **같은 와이파이**에 연결한다.
3. 폰 크롬 브라우저에서 `http://PC의_IP주소:포트번호` 로 접속한다.
4. 크롬 메뉴에서 "홈 화면에 추가"를 누르면 아이콘이 생긴다.

## 6. 진행 이력

- 2026-11-06: 계획서 작성, Sprint 0(뼈대) 구현.
- 2026-11-06: Sprint 1(MVP) 구현 — 종목 입력(구분/종목명/수량/평균단가/현재가),
  평가금액·손익·수익률 자동 계산, localStorage 저장. 국내(₩)·미국($) 합계는
  환율 미반영이라 섞지 않고 따로 표시. 색상은 한국 관행대로 상승=빨강, 하락=파랑.
  서비스 워커 캐시 버전은 파일을 바꿀 때마다 올려야 함(`CACHE_NAME`).
- 2026-11-06: Sprint 2 구현 — 입력 방식을 거래내역(날짜/구분/종목명/매수·매도/수량/단가/수수료)
  으로 전환. 보유수량·평균단가는 거래내역에서 자동 계산(매수=가중평균 재계산, 매도=수량만
  차감, 평균단가 유지). 현재가는 Sprint 4 전까지 종목별로 직접 입력(보유 종목 카드 안 입력칸).
  Sprint 1 데이터(`stockHoldings_v1`)는 최초 매수 거래로 1회 자동 변환.
  저장 키: `stockTransactions_v1`(거래내역), `stockCurrentPrices_v1`(현재가).
- 2026-11-06: Sprint 3(대시보드) 구현 — ① 시장별(국내/미국) 평가금액·손익 스탯 타일,
  ② 종목 비중(평가금액 기준 part-to-whole 가로 막대 + 범례, 상위 7종목 색 구분·나머지는
  "기타"로 묶음), ③ 수익률 순위(0% 기준선 양쪽으로 뻗는 막대, %는 단위가 없어 국내·미국을
  한 목록에서 비교). 차트 색상은 `dataviz` 스킬 기준으로 다크 배경(#0f172a)에서
  색맹 접근성 검증(`validate_palette.js`) 통과한 팔레트 사용. 원형(파이) 차트는
  비교가 어려워 제외하고 막대+범례로 대체.
- 2026-11-06: Sprint 4(현재가 자동 조회) 구현 — 무료 데이터 소스 조사 결과, 이 앱은
  빌드 도구·백엔드 서버 없이 **폰 브라우저가 직접 fetch()** 해야 하므로 CORS 허용 여부가
  관건. 야후 파이낸스·네이버 금융은 브라우저 직접 호출이 CORS로 막힘(확인 완료), 공용
  CORS 프록시 3종(corsproxy.io, api.codetabs.com, api.allorigins.win)도 테스트 시점
  기준 전부 불안정(키 필요/다운)해서 제외. **Twelve Data**를 채택 — 브라우저 직접 호출이
  CORS로 허용되고, 무료 키 하나로 국내(KRX, `exchange=KRX` 파라미터)·미국 주식을
  같은 API로 조회 가능(한국 응답은 사용자의 실제 키로 추가 확인 필요). 분당 8회 제한,
  일일 호출 상한 없음.
  - 구현: 종목별 "시세 코드"(국내는 종목코드, 미국은 티커) 입력칸 + "조회" 버튼,
    "전체 종목 시세 새로고침" 버튼(호출 간 0.3초 간격, 분당 제한 대비). API 키는
    설정 카드에 입력하면 `stockApiKey_v1`에 저장(폰 안에만, 조회 시에만 전송).
    저장 키: `stockSymbols_v1`(시세 코드).
  - **Plan B 설계**: 조회 로직을 `fetchCurrentPrice()` 함수 하나에 모아둠 — 나중에
    Twelve Data의 KRX 응답이 안 되거나 제한에 걸리면, 이 함수만 다른 소스(Finnhub는

  - **실사용 테스트 결과(사용자 실제 키로 확인, 2026-11-06)**: 미국 주식(GOOGL, COIN,

    `srtnCd`(종목코드)+`beginBasDt`~`endBasDt`(날짜 범위, 영업일 모를 수 있어 9일
